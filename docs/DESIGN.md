# 디자인 기준

기업 인사이트의 모든 화면(종목 화면, 운영자 페이지, 이후의 홈·랜딩)이 따르는 규칙이다. 기준 화면은 `demo.html`, 토큰·부품·상태·아이콘을 한 페이지에 모은 것은 `design-system.html`이다. 실제 화면(Thymeleaf)은 이 문서의 토큰과 규칙을 그대로 옮긴다. 규칙을 바꾸면 이 문서와 두 페이지를 함께 고친다(두 페이지의 공통 CSS는 같은 내용이다).

## 0. 분위기

**다크, 테크, AI, 모던, 심플, 가독성, 글래스모피즘.** 색은 무채색(살짝 차가운 회색 계열)만 쓰고, 뜻이 있는 색은 호재(빨강)·악재(파랑)·AI(보라) 셋뿐이다. **검정·회색은 한 계열의 회색 단계표(3-1) 중 하나만 써서 화면 전체의 검정이 같은 톤으로 보이게 한다.** 바탕은 거의 검정 한 색이고(빛·격자·무늬 없음), 카드는 한 단계 밝은 면에 가는 회색 테두리, 카드 안의 칸과 버튼은 또 한 단계 밝은 면이다. 유리(뒤를 흐리는 반투명)는 위에 떠 있는 상단 바와 공시 패널에만 쓴다. 글자와 판단 표시는 언제나 단단하고 또렷하게 둔다. 효과와 가독성이 부딪히면 가독성이 이긴다.

## 1. 원칙

1. **판단과 근거가 먼저 읽힌다.** 화면에서 가장 크고 진한 것은 판단 단계 이름이고, 그다음이 근거 공시다. 장식은 이 순서를 흐리지 않는다.
2. **AI는 근거와 함께 말한다.** AI가 한 일(요약, 판정)은 보라색으로 표시하고, 바로 옆에 원문 링크나 판정 방법을 둔다.
3. **매일 봐도 피곤하지 않다.** 순수 검정과 순수 흰색을 쓰지 않고, 움직이는 연출 대신 상태가 바뀐 것을 알리는 반응만 둔다.
4. **한눈에 들어온다.** 한 줄에는 한 가지 말만 한다. 쉬운 말이 먼저이고, 원문과 세부 정보는 그 아래나 공시 패널로 보낸다.

## 2. 화면 종류별 효과 수준

| 화면 | 효과 |
|---|---|
| 랜딩 (MVP 이후) | 연출 허용(빛줄기, 반투명 카드, 들어올 때 나타나는 움직임). 연출은 이 화면에만 쓴다 |
| 일반 화면 (종목 화면, 홈) | 위에 떠 있는 유리(상단 바, 공시 패널) + 상태 반응(색 전환, 패널 열림, 새 항목 밝힘) |
| 작업 화면 (운영자 페이지) | 유리 없이 같은 회색 단계표의 불투명 면만. 효과 없음 |

## 3. 색

**색은 모두 토큰으로만 쓴다.** 컴포넌트에 `#fff`나 `rgba(255,255,255,…)`를 직접 쓰지 않는다. 라이트 모드를 붙일 때 토큰 블록 하나만 더하면 되게 하려는 것이다.

### 3-1. 회색 단계표와 토큰

**검정·회색은 아래 단계표의 값만 쓴다.** 모두 같은 계열(살짝 차가운 회색)이라 어디에 놓여도 같은 톤으로 보인다. 반투명 흰 빛을 겹쳐 회색을 만들지 않는다(겹치는 바탕에 따라 톤이 달라진다).

### 3-2. 색의 뜻

- **빨강은 호재, 파랑은 악재, 회색은 중립**이다. 이 세 색은 이 뜻으로만 쓴다(오류, 경고, 링크에 쓰지 않는다).
- **색만으로 구분하지 않는다.** 호재·악재·중립 표시에는 항상 "호재", "악재", "중립" 글자를 함께 쓴다(판단 이름, 칩, 타임라인 둘째 줄 앞). **▲·▼ 같은 모양 기호는 쓰지 않는다.** 빨강 ▲·파랑 ▼는 주가 등락 표시와 같아 판단이 시세처럼 읽히고, 작은 기호는 가독성이 떨어진다. 뜻은 글자가 전한다.
- **보라는 AI가 한 일에만** 쓴다: "AI 요약" 칩, AI가 쓴 글의 칸(판단 카드의 한 줄 요약, 공시 패널의 3줄 요약은 옅은 보라 면 + 보라 테두리 칸에 넣는다), "AI 판정" 표시. 선택 상태, 링크, 강조, 그래프에는 쓰지 않는다. 빨강과 파랑이 겹쳐 보라처럼 보이는 곳도 만들지 않는다.
- **선택된 탭·버튼은 흰색**(`--text` 바탕에 `--bg` 글자)이다. 강조색을 따로 두지 않는다.
- 초록(해외에서 상승을 뜻함)과 노랑(경고로 읽힘)은 쓰지 않는다.
- 판단 추이 그래프의 선 색은 판단 단계의 경계를 따른다. 약한 호재 경계 위는 빨강, 약한 악재 경계 아래는 파랑, 그 사이(중립)는 회색이다.
- 호재·악재 칩과 AI 칩은 불투명한 `--card` 위에 겹친 색으로 고정한다. 선택된 줄 위에 올라가도 글자 대비가 변하지 않게 하려는 것이다.
- 바탕과 면, 선은 회색 단계표만 쓴다. 바탕에 빛·그라데이션·무늬를 깔지 않는다.
- **판단 이름(약한 호재 등)은 상자 없이 큰 글자로 쓴다.** 호재는 빨강, 악재는 파랑, 중립은 본문색, 판단 보류는 보조색이다. 상자(면 + 테두리)를 두르면 버튼과 모양이 같아져 눌러야 할 것처럼 보이고, 바로 아래 판단 막대가 이미 위치를 보여 준다. 강한·약한은 글자와 막대 길이로 구분한다.

### 3-2-1. 유리를 쓰는 규칙

- 유리는 **위에 떠 있는 것**(상단 바, 공시 패널)에만 쓴다: 바탕색(950) 80% + 뒤 흐림 24px. 스크롤하는 글이 그 아래로 지나갈 때 흐리게 비친다.
- 카드, 칩, 버튼, 카드 안의 칸, 자동완성 목록은 불투명한 회색 단계 면이다. 유리 위에 유리를 겹치지 않는다.
- **판단 카드도 단색이다.** 유리 판단 카드(925를 60% + 흐림)는 뒤에 무엇이 지나가느냐에 따라 면의 밝기가 바뀌어, 옅은 글씨의 대비가 6.3 : 1(뒤가 바탕)에서 2.9 : 1(뒤에 보조 글씨)까지 떨어진다. 판단 카드는 화면에 고정하지 않아 뒤로 지나가는 것도 없다. 비교는 `design-system.html`의 "판단 카드 유리 비교".
- 카드의 테두리는 1px `--line`이고, 판단 카드만 2px `--line-strong`에 윗변을 한 단계 밝게(`--line-selected`) 한다. 그림자는 쓰지 않는다.
- AI 칩에만 아주 옅은 보라 빛(바깥 번짐 14px)을 둔다. 다른 요소에는 빛 번짐을 쓰지 않는다.
- 유리를 못 쓰는 브라우저와 "투명도 줄이기"를 켠 사용자에게는 상단 바와 패널을 불투명한 바탕색으로 보여준다.

### 3-3. 대비 (WCAG 식으로 계산한 값)

`design-system.html`이 토큰 값으로 직접 계산해 보여준다(반투명 색은 아래 면에 합성해서 계산).

| 조합 | 대비 |
|---|---|
| 본문 `--text` / 바탕, 카드, 안쪽 칸, 선택된 줄, 보조 버튼 누름 | 15.7, 14.9, 14.0, 11.7, 8.2 : 1 |
| 보조 `--text-sub` / 바탕, 카드, 안쪽 칸, 선택된 줄 | 7.8, 7.4, 6.9, 5.8 : 1 |
| 옅은 글씨 `--text-faint` / 바탕, 카드, 안쪽 칸, 선택된 줄 | 6.5, 6.2, 5.8, 4.9 : 1 |
| 주 버튼 글자 `--on-primary` / 기본, hover, 누름 | 15.7, 13.5, 7.8 : 1 |
| 호재 빨강·악재 파랑 / 카드(판단 이름 포함), 안쪽 칸, 선택된 줄, 칩 면 | 6.3, 5.9, 5.0, 5.4 ~ 5.5 : 1 |
| AI 보라 / 카드, 안쪽 칸, AI 칩, AI가 쓴 글의 칸 | 6.9, 6.5, 5.8, 6.4 : 1 |
| AI가 쓴 글의 칸 위 본문, 옅은 글씨 | 13.8, 5.8 : 1 |
| 포커스 테두리 / 바탕, 카드 (선이라 3 : 1 기준) | 7.3, 7.2 : 1 |

- **보조 글씨를 `--g700` 면 위에 쓰지 않는다**(4.1 : 1). 보조 버튼을 누를 때(700 면)는 글자가 본문색이라 괜찮다.
- 본문 대비를 14 ~ 16 : 1로 둔다. 20 : 1이 넘으면(순수 검정 위 순수 흰색) 글자가 번져 보이고 눈이 피곤하다.
- 빨강과 파랑은 밝기가 같아서(상대 휘도 0.299) 어느 한쪽이 더 눈에 띄지 않는다.
- 새 조합을 만들면 그 바탕 위에서 다시 계산하고, 글자는 4.5 : 1 이상을 지킨다. 분석 실패 때 흐리게 보이는 지난 판단(투명도 .6, 본문 5.9 : 1)과 쓸 수 없는 상태(투명도 .4, WCAG 예외)만 기준 밖이다.

## 4. 글자

- 글꼴: Pretendard(가변 굵기). 한글과 영문·숫자의 모양이 고르고 화면용으로 만들어져 모던·테크 분위기에 맞는다. 없으면 시스템 글꼴(-apple-system, Apple SD Gothic Neo, 맑은 고딕) 순서다. 실제 화면에서는 글꼴 파일을 직접 두고 쓴다.
- **글자는 아래 여덟 역할만 쓴다.** 크기는 13·15·17·20·28px(폭 600px 이하에서 화면 제목 24, 큰 값 17)과 랜딩 전용 44px뿐이다. 굵기는 400·600·700·800뿐이다.

| 역할 | 크기 / 굵기 / 줄 간격 | 색 | 쓰는 곳 |
|---|---|---|---|
| 화면 제목 | 28 / 800 / 1.3 | 본문·호재·악재·보조 | 회사 이름, 판단 이름(판단이 화면에서 가장 크고 진하다) |
| 큰 값 | 20 / 800 / 1.3 | 본문 | 패널 제목, 실적 숫자 |
| 카드 제목 | 17 / 700 / 1.4 | 본문 | 모든 카드 제목(**판단 카드의 "최근 공시 기준 판단"도 같다**), 상태 안내의 제목, 로고 글자 |
| 줄 제목 | 15 / 600 / 1.5 | 본문 | 목록 한 줄의 쉬운 말(판단 근거, 타임라인, 날짜 목록이 모두 같다), 버튼 글자, 빈 상태의 제목 |
| 본문 | 15 / 400 / 1.6 | 본문 | 문단, AI 한 줄 요약과 3줄 요약 |
| 칸 제목 | 13 / 700 / 1.5 | 보조 | 판단 근거, 반대로 볼 점, 패널 칸 제목, 타임라인 묶음 이름 |
| 라벨 | 13 / 600 / 1.5 | 보조·뜻 색 | 칩, AI 칩, 세그먼트, 글자형 버튼 |
| 메타 | 13 / 400 / 1.5 | 보조(설명·고지) 또는 옅은 색(날짜·출처·원문 제목) | 한 줄 아래의 보조 정보 |

- 한 카드 안의 글자 위계는 세 단계까지다: 카드 제목 / 줄 제목·본문 / 칸 제목·라벨·메타.
- 자간은 −0.01em, 화면 제목 −0.03em, 큰 값과 카드 제목 −0.02em, 13px 글자는 0이다.
- 숫자는 `tabular-nums`로 자리를 맞춘다.
- 금액은 읽기 쉬운 단위로 쓴다: 1조 원 이상은 "237.3조", "1.63조"(소수 둘째 자리까지), 그 아래는 "3,900억". "2,373,000억"처럼 쓰지 않는다.
- 한글은 `word-break: keep-all`로 단어 중간에서 줄을 바꾸지 않고, 긴 공시 제목은 `overflow-wrap: anywhere`로 넘치지 않게 한다.
- 공시 제목은 DART 원문 그대로 쓴다. 줄이거나 고치지 않는다. 다만 목록과 패널의 주인공은 쉬운 말 한 줄이고, 원문 제목은 그 아래 보조 줄에 둔다(8절).

## 5. 모양과 간격

- **간격은 4px 단계 일곱 개만 쓴다:** `--s1` 4 / `--s2` 8 / `--s3` 12 / `--s4` 16 / `--s6` 24 / `--s8` 32 / `--s12` 48px.

| 간격 | 쓰는 곳 |
|---|---|
| 4 | 아이콘과 13px 글자 사이, 제목과 그 아래 메타 사이, 줄 제목과 메타 사이 |
| 8 | 아이콘과 15px 글자 사이, 칩 안 여백, 버튼끼리, 메타 문단 위 |
| 12 | 목록 줄 안 여백, 상단 바 위아래, 날짜 목록 위 |
| 16 | 카드 안의 칸 안 여백, 카드 안 묶음 사이, 화면 양옆 여백, 버튼 양옆 여백 |
| 24 | 카드 안 여백, 카드 사이, 패널 안 여백, 묶음 제목 위 |
| 32 / 48 | 화면 위 / 아래 여백 |

- **테두리가 있는 모양은 모두 둥근 사각형 한 가족이고, 모서리는 세 가지만 쓴다:** `--r-lg` 16px(카드, 판단 카드, 공시 패널, 시트) / `--r-md` 12px(카드 안의 칸, 버튼, 세그먼트, 입력창, 목록 줄, 자동완성, 말풍선, 로고 칸) / `--r-sm` 8px(높이 24px의 칩, 판단 막대). **양끝이 반원인 알약 모양은 쓰지 않는다**(카드 안에서 둥근 사각형과 섞이면 모양이 두 종류로 보여 통일감을 해친다). 타임라인의 점은 표시라 둥근 점이고, 그래프의 막대(1px)는 그림이라 예외다.
- 부품 높이: 누르는 것 44px(세그먼트만 36px, 손가락으로 누르는 기기에서는 44px), 칩 24px, 판단 막대 8px.
- **묶음은 면으로 나눈다.** 카드는 회색 단계 925 면이고 테두리는 1px `--line`뿐이다. 카드 안의 칸은 `--surface` 면으로 한 단계 들인다. 그 밖의 선은 목록의 줄 나눔(`--line`)에만 쓴다.
- **2px 테두리는 판단 카드만** 쓴다(화면의 기준점). 왼쪽 세로 막대 장식은 쓰지 않는다.
- 레이아웃: **화면 폭과 상관없이 한 단**(최대 폭 720px, 가운데)이다. 두 단으로 나누면 판단과 나머지가 동시에 눈에 들어와 시선이 흩어지고, 두 단의 길이가 달라 한쪽이 비며, 판단이 주인공이라는 위계가 약해진다. 양옆 여백 16px 이상(노치가 있는 기기는 안전 영역만큼 더). 카드 사이 24px, 카드 안 여백 24px(폭 600px 이하에서는 위아래 24 / 양옆 16px), 목록 한 줄의 안 여백 12px.

## 6. 부품과 상태

### 6-1. 누를 수 있는 부품

실제 `button`, `a`만 쓴다. **hover는 지금 면보다 한 단계, 누름·선택은 두 단계 밝게** 하고, 크기와 위치는 바꾸지 않는다(scale, 이동 없음). 색 전환은 0.2초.

| 부품 | 기본 | hover | 누름 | 선택 | 포커스 | 쓸 수 없음 |
|---|---|---|---|---|---|---|
| 주 버튼 (밝은 면. 한 화면·패널에 하나: DART 원문 보기, 오류의 다시 불러오기) | 200 면, 950 글자 | 300 면 | 400 면 | — | 공통 | 공통 |
| 보조 버튼 (다시 불러오기 등) | 900 면, 700 테두리 | 800 면, 600 테두리 | 700 면 | — | 공통 | 공통 |
| 글자형 버튼 (계산 방식, 나머지 근거, 이전·다음) | 면 없음, 보조 글씨 | 900 면, 본문 글씨 | 800 면 | — | 공통 | 공통 |
| 아이콘 버튼 (닫기, 44px 정사각) | 면 없음 | 900 면 | 800 면 | — | 공통 | 공통 |
| 세그먼트 (기간) | 900 면, 700 테두리, 보조 글씨 | 800 면, 600 테두리, 본문 글씨 | 700 면 | 200 면, 950 글자, 굵게 | 공통 | 공통 |
| 입력창 (검색) | 900 면, 800 테두리 | 700 테두리 | — | — | 600 테두리 + 공통 | 공통 |
| 목록 한 줄 (판단 근거, 타임라인, 날짜 목록) | 면 없음 | 900 면 | 800 면 | 800 면(패널에 열린 줄) | 공통 | — |

- **포커스(공통):** 2px `--focus` 테두리, 3px 띄움. **절대 빼지 않는다.**
- **쓸 수 없음(공통):** 투명도 .4, 커서 기본, 눌러도 반응 없음. 이유가 있으면 가까이에 글로 쓴다(예: 공시가 없는 회사의 기간 버튼).
- 누를 수 없는 카드에는 hover를 두지 않는다.

### 6-2. 표시 부품 (누를 수 없음, 상태 없음)

- **칩**(24px, 모서리 8, 라벨 글자): 호재·악재·중립(기호 없이 글자. 면은 `--card` 위에 옅은 색을 겹쳐 고정), AI 칩(보라 + 옅은 빛), 일반 칩(700 테두리).
- **판단 이름**(화면 제목 글자, 상자 없음): 다섯 단계 + 판단 보류(보조색 글자, 카드 테두리가 점선).
- **카드**(925 면, 800 테두리, 16), **판단 카드**(2px), **카드 안의 칸**(900 면, 12, 안 여백 16), **AI가 쓴 글의 칸**(보라 6% 면, 32% 테두리).
- **공시 패널**: 유리(3-2-1), 폭 440px, 640px 이하에서는 아래 시트.

### 6-3. 아이콘

- **24 칸에 직접 그린 선 아이콘**이다. 선 굵기는 크기와 상관없이 1.5px(`vector-effect: non-scaling-stroke`), 끝과 꺾임은 둥글게. 받은 참고 자료의 아이콘을 옮기지 않는다.
- 크기: 13px 글자 옆은 16px, 버튼·입력창(15px 글자)은 20px. 색은 글자색을 따른다.
- 세트: **열기**(오른쪽 꺾쇠. 누르면 패널이 열리는 줄의 끝), **이전**(왼쪽 꺾쇠), **펼치기**(아래 꺾쇠. 열리면 180도 돈다), **바깥 링크**(상자 밖으로 나가는 화살표. DART 원문, 새 창), **닫기**(엑스), **다시 불러오기**(둥근 화살표), **검색**(돋보기).
- 호재·악재·중립에는 기호를 붙이지 않는다(3-2). 열기 꺾쇠, 바깥 링크 같은 기능 아이콘도 ›·↗ 같은 글자 기호가 아니라 위 세트로 그린다.
- 아이콘은 화면 읽기에서 숨기고(`aria-hidden`), 아이콘만 있는 버튼에는 이름(`aria-label`)을 붙인다. 새 창으로 여는 링크에는 "(새 창)"을 화면 읽기용으로 붙인다.

### 6-4. 화면 상태

**판단 카드의 상태 다섯 가지**: 호재 / 악재 / 중립 / 판단 보류(판단 이름을 보조색으로, 카드 테두리를 점선으로) / 분석 실패(지난 판단을 투명도 .6으로 흐리게 보여주고, 원인 한 줄과 "다시 불러오기" 보조 버튼).

**화면 전체의 상태** (데모 화면 아래 "데모 화면 상태"로 볼 수 있다)

| 상태 | 표현 |
|---|---|
| 불러오는 중 | 실제 배치와 같은 자리에 900 면(자리 표시). 1.6초에 한 번 옅어진다. 화면 읽기에는 "불러오는 중이에요"를 알리고 `aria-busy`를 켠다 |
| 불러오기 오류 | 카드 하나에 카드 제목("회사 정보를 불러오지 못했어요"), 원인과 다음 행동 한 줄, 주 버튼 "다시 불러오기"와 보조 버튼 "DART에서 보기". 빨강을 쓰지 않는다(빨강은 호재) |
| 공시가 없는 회사 | 판단 카드는 판단 보류("아직 모은 공시가 없어…"), 판단 추이·실적·타임라인은 빈 상태 칸. 기간 버튼은 쓸 수 없음 |
| 검색 결과 없음 | 자동완성 자리에 검색 아이콘 + "‘입력한 말’에 맞는 회사가 없어요" + 찾는 방법 한 줄 |
| 분석 실패 | 위의 판단 카드 상태 |

**빈 상태 칸**: 카드 안의 칸(900 면) 안에 줄 제목(왜 없는지)과 메타(언제 생기는지).

**비어 있거나 없는 것은 이유를 말한다.** "이날 들어온 공시는 없어요", "중립 공시는 요약하지 않아요", "요약을 아직 만들지 않았어요. 다음 분석 때 채워져요"처럼 왜 없는지와 언제 생기는지를 쓴다.

## 7. 움직임

- 기본 전환: 0.2초, `cubic-bezier(0.4, 0, 0.2, 1)`. 이 하나만 쓴다.
- 쓰는 곳: 색·테두리 전환, 펼치기 아이콘 회전, 패널 열림(오른쪽에서 밀려 들어옴, 시트는 아래에서), 막 나타남, 새로 들어온 항목·다시 불러온 판단 카드를 1.2초 밝혔다가 원래대로, 불러오는 중 자리 표시가 1.6초에 한 번 옅어짐.
- 쓰지 않는 것: 크기 변화, 흔들림, 튀는 곡선, 스크롤에 따라 움직이는 연출, 저절로 도는 슬라이드, 숫자 올라가는 효과.
- 사용자가 움직임 줄이기(`prefers-reduced-motion`)를 켜 두었으면 전환과 애니메이션을 모두 끈다.

## 8. 화면 패턴

- **종목 화면은 위에서 아래로 한 줄 흐름**이다: 회사 이름 → 판단 카드 → 판단 추이 → 실적(접힘) → 타임라인. 넓은 화면에서도 같은 순서의 한 단이다. 판단 카드는 화면에 고정하지 않는다(카드가 화면보다 길면 카드 안에 스크롤이 하나 더 생겨 불편하다).
- **카드 제목은 짧은 명사형**이다: "판단 추이", "실적", "타임라인". 질문형("…어때요?")을 쓰지 않는다.
- **로고:** 모서리가 둥근 사각 칸(32px, 모서리 12px)을 `--text` 면으로 채우고, 겹친 층 아이콘(18px)을 `--bg` 색으로 넣는다. 옆에 "기업 인사이트"(카드 제목 글자).
- **상단 바:** 로고와 검색창(왼쪽에 검색 아이콘). 검색창은 최대 폭 420px이고 넓은 화면에서도 끝까지 늘리지 않는다.
- **회사 머리:** 회사 이름이 먼저, 그 아래 한 줄에 종목코드 · 시장 · 업종. 판단 카드와 떨어뜨린다.
- **판단 막대:** 막대 양 끝에 "악재"와 "호재"만 작게 붙인다. 가운데(중립)는 막대의 홈으로 보인다.
- **그래프:** 점선 격자를 쓰지 않는다. 판단 추이는 중립 구간만 옅은 띠로 깔고, 이름표는 호재·중립·악재 셋이다. 판단 보류 기간(호재·악재 공시가 없던 날이 이어진 구간)은 선을 회색 점선으로 그려 중립과 구분한다. 점선은 이 뜻으로만 쓴다. 이름표와 설명은 그래프 밖(오른쪽 끝, 아래 안내 한 줄)에 둔다.
- **공시 한 줄(판단 근거, 반대로 볼 수 있는 점, 타임라인, 날짜 목록)은 두 줄로 쓴다.** 공시 한 건은 어디에 있든 같은 줄 모양이다. "반대로 볼 수 있는 점"도 판단 근거처럼 칸 제목 아래 같은 줄로 두고 회색 칸에 넣지 않는다(줄의 hover 면이 칸과 같은 900이라 보이지 않는다).
  - 첫 줄: 무슨 일인지 쉬운 말 한 줄. 사실만 쓴다("3분기 영업이익이 1년 전보다 13% 증가", "자기주식 3조 원 취득 결정"). 판정 이유("호재로 정한 유형이라")는 쓰지 않는다.
  - 둘째 줄(메타, 옅은 색): 날짜 · DART 원문 제목. AI가 판정한 공시만 끝에 보라색 "AI 판정"을 붙인다.
  - 공시 유형, 크기, 판정 방법, 요약은 목록에 쓰지 않고 공시 패널에서 보여준다.
  - **칩은 한 줄에 하나까지**(호재·악재·중립). 판단 근거·날짜 목록의 줄은 휴대폰에서도 칩(면이 있는 "호재" 글자)을 줄 앞에 둔다. 타임라인은 칩 없이 색 점과 둘째 줄 앞의 색 글자("호재 ·")를 쓴다.
- **설명 문단은 접는다.** 판단 카드의 계산 방식은 "계산 방식"을 눌러야 보인다. 고지 한 줄은 늘 보인다.
- **탭은 쓰지 않는다.** 정보가 많으면 덜 중요한 것을 접는다(나머지 근거, 실적, 계산 방식). 기간처럼 같은 내용을 다른 범위로 보는 선택만 세그먼트 버튼으로 둔다.
- **공시 한 건은 공시 패널로 연다.** 화면 오른쪽에서 열리는 폭 440px 패널이고, 폭 640px 이하에서는 아래에서 올라오는 시트(화면 높이의 88%까지)다. 어디서 누르든 같은 패널이 열린다.
  - 패널 내용 순서: 호재·악재와 크기, 날짜·유형 → 제목(쉬운 말 한 줄) → DART 원문 제목 → 지금 판단에 들어가 있는지 → AI 3줄 요약 → 어떻게 판정했나 → DART 원문 링크 → 고지.
  - 열면 포커스가 닫기 버튼으로 가고 뒤 화면은 누를 수 없게 막는다. Esc, 바깥 막 누르기, 닫기 버튼, 뒤로 가기로 닫힌다. 닫으면 포커스가 누른 줄로 돌아간다.
  - 패널이 열린 동안 그 공시의 줄은 선택 상태로 보인다.
  - 공시마다 주소(접수번호)가 붙는다. 패널 안의 이전·다음은 주소를 바꾸기만 하고 뒤로 가기 기록을 쌓지 않는다.
- **소식은 세로 타임라인**으로 보여준다: 다가오는 일정 → 오늘 → 지난 공시. 선 위의 표시는 색 점(호재 빨강, 악재 파랑, 중립 회색), 예정은 빈 점, 오늘은 큰 점이고, 뜻은 둘째 줄 앞의 글자가 전한다.
- 숫자 점수는 공개 화면에 보이지 않는다. 판단은 다섯 단계 이름과 수평 막대로 보여준다.

## 9. 접근성

- 글자 대비 4.5 : 1 이상(3-3).
- 손가락으로 누르는 기기에서 누르는 곳은 44px 이상이다.
- 누르는 것은 실제 `button`과 `a`로 만든다. `div`에 클릭을 달지 않는다.
- 그래프는 키보드(좌우 방향키)로도 날짜를 옮길 수 있고, 같은 내용을 글로도 보여준다.
- 색만으로 뜻을 전하지 않는다(3-2).

## 10. 문구

- 해요체로 쓴다. 짧게, 사실만. 목록의 쉬운 말 한 줄은 명사로 끝내도 된다("…13% 증가", "…취득 결정").
- 매수·매도·추천·목표가·예측처럼 읽히는 표현과 시세를 안내하는 표현을 쓰지 않는다.
- 판단은 "최근 공시 기준"으로 범위를 밝힌다.
- 오류는 원인과 다음 행동을 쓰고 사과하지 않는다. 예: "11.06 공시 분석이 끝나지 않아 11.05 판단을 보여주고 있어요. 새 공시는 다음 분석 때 반영돼요."
- 판단 카드, 공시 패널, 화면 아래에 "AI 요약은 틀릴 수 있으며 투자 권유가 아니에요" 고지를 둔다. 공시·재무의 출처(DART)를 밝힌다.

## 11. 라이트 모드 (이후)

지금은 어두운 토큰 한 벌만 있다(`color-scheme: dark`). 라이트 모드는 3-1의 토큰 블록을 하나 더해 붙인다(회색 단계표를 밝은 쪽으로 뒤집고, 호재·악재·AI 색은 밝은 바탕에서 대비를 다시 계산한다). 시스템 설정을 따를지 전환 버튼을 둘지는 붙일 때 정한다.
