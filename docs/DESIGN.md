# 디자인 기준

기업 인사이트의 모든 화면(종목 화면, 운영자 페이지, 이후의 홈·랜딩)이 따르는 규칙이다. 기준 화면은 `demo.html`이고, 실제 화면(Thymeleaf)은 이 문서의 토큰과 규칙을 그대로 옮긴다. 규칙을 바꾸면 이 문서와 데모를 함께 고친다.

## 1. 원칙

1. **판단과 근거가 먼저 읽힌다.** 화면에서 가장 크고 진한 것은 판단 단계 이름이고, 그다음이 근거 공시다. 장식은 이 순서를 흐리지 않는다.
2. **AI는 근거와 함께 말한다.** AI가 한 일(요약, 판정)은 보라색으로 표시하고, 바로 옆에 원문 링크나 판정 방법을 둔다.
3. **매일 봐도 피곤하지 않다.** 움직이는 연출은 쓰지 않고, 상태가 바뀐 것을 알리는 반응만 둔다.

## 2. 화면 종류별 효과 수준

| 화면 | 효과 |
|---|---|
| 랜딩 (MVP 이후) | 연출 허용(빛줄기, 반투명 카드). 이 화면에만 쓴다 |
| 일반 화면 (종목 화면, 홈) | 상태 반응만(색 전환, 패널 열림, 새 항목 밝힘) |
| 작업 화면 (운영자 페이지) | 효과 없음. 색 전환도 생략할 수 있다 |

## 3. 색

**색은 모두 토큰으로만 쓴다.** 컴포넌트에 `#fff`나 `rgba(255,255,255,…)`를 직접 쓰지 않는다. 흰 빛과 선은 `rgba(var(--tint), 투명도)`로 쓴다. 라이트 모드를 붙일 때 토큰 블록 하나만 더하면 되게 하려는 것이다.

### 3-1. 토큰

| 토큰 | 값 | 쓰는 곳 |
|---|---|---|
| `--bg` | `#000` | 바탕 |
| `--surface` | `#0b0d10` | 카드 안의 한 단계 들어간 칸(반대로 볼 점, 날짜 목록, 패널의 요약 칸), 입력창 |
| `--text` | `#fafafa` | 본문, 제목 |
| `--text-sub` | `#a1a1a1` | 보조 글씨, 칸 제목 |
| `--text-faint` | `#888888` | 날짜, 출처, 설명 같은 가장 옅은 글씨 |
| `--tint` | `255,255,255` | 선과 채움의 바탕색(라이트 모드에서 검정으로 바꾼다) |
| `--line` / `--line-hover` / `--line-selected` / `--line-strong` | tint .08 / .16 / .30 / .28 | 카드 테두리 / 누를 수 있는 것의 테두리·hover / 선택 / 판단 카드 테두리 |
| `--fill-hover` / `--fill-selected` | tint .05 / .11 | hover 배경 / 누름·선택 배경 |
| `--focus` | tint .45 | 키보드 포커스 테두리 |
| `--up` / `--up-soft` | `#f04452` / 14% | 호재 |
| `--down` / `--down-soft` | `#3182f6` / 16% | 악재 |
| `--flat` / `--flat-soft` | `#a1a1a1` / tint .08 | 중립 |
| `--ai` / `--ai-soft` | `#a78bfa` / 14% | AI가 한 일 |
| `--scrim` | 검정 60% | 패널이 열렸을 때 뒤 화면을 덮는 막 |

### 3-2. 색의 뜻

- **빨강은 호재, 파랑은 악재, 회색은 중립**이다. 이 세 색은 이 뜻으로만 쓴다(오류, 경고, 링크에 쓰지 않는다).
- **색만으로 구분하지 않는다.** 호재·악재 표시에는 항상 모양(▲ 호재, ▼ 악재, — 중립)과 글자를 함께 붙인다.
- **보라는 AI가 한 일에만** 쓴다: "AI 요약" 칩, AI 한 줄 요약, "판정 AI" 표시. 선택 상태, 링크, 강조, 그래프에는 쓰지 않는다. 빨강과 파랑이 겹쳐 보라처럼 보이는 곳도 만들지 않는다.
- **선택된 탭·버튼은 흰색**(`--text` 바탕에 `--bg` 글자)이다. 강조색을 따로 두지 않는다.
- 초록(해외에서 상승을 뜻함)과 노랑(경고로 읽힘)은 쓰지 않는다.
- 판단 추이 그래프의 선 색은 판단 단계의 경계를 따른다. 약한 호재 경계 위는 빨강, 약한 악재 경계 아래는 파랑, 그 사이(중립)는 회색이다.
- 호재·악재 칩의 배경은 바탕(`--bg`) 위에 한 번 겹친 색으로 고정한다. 칩이 선택된 줄이나 hover 배경 위에 올라가도 글자 대비가 떨어지지 않게 하려는 것이다.

### 3-3. 대비 (WCAG 식으로 계산한 값)

| 조합 | 대비 |
|---|---|
| 본문 `--text` / 검정 | 20.1 : 1 |
| 보조 `--text-sub` / 검정 | 8.1 : 1 |
| 옅은 글씨 `--text-faint` / 검정, `--surface`, 선택 배경 | 5.9, 5.5, 4.8 : 1 |
| 호재 빨강 / 검정, 호재 칩 배경 | 5.7, 5.1 : 1 |
| 악재 파랑 / 검정, 악재 칩 배경 | 5.7, 4.9 : 1 |
| AI 보라 / AI 칩 배경 | 6.7 : 1 |
| 강한 호재·악재 배지(색 바탕에 검정 글자) | 5.7 : 1 |

빨강과 파랑은 밝기가 같아서 어느 한쪽이 더 눈에 띄지 않는다. 새 조합을 만들면 그 바탕 위에서 다시 계산하고, 글자는 4.5 : 1 이상을 지킨다.

## 4. 글자

- 글꼴: Noto Sans KR. 없으면 Apple SD Gothic Neo, 맑은 고딕, system-ui 순서다.
- 크기: 13(설명·메타) / 15(본문) / 17(카드 제목, 강조 본문) / 20(판단 배지, 패널 제목) / 24(폭 600px 이하의 회사 이름) / 28(회사 이름) / 44(랜딩 전용)px. 이 밖의 크기는 쓰지 않는다.
- 굵기: 400(본문) / 500(목록 제목) / 700(칸 제목, 라벨) / 800(판단 배지, 회사 이름).
- 줄 간격 1.6, 자간 −0.01em(큰 제목은 −0.02 ~ −0.03em).
- 숫자는 `tabular-nums`로 자리를 맞춘다.
- 한글은 `word-break: keep-all`로 단어 중간에서 줄을 바꾸지 않고, 긴 공시 제목은 `overflow-wrap: anywhere`로 넘치지 않게 한다.
- 공시 제목은 DART 원문 그대로 쓴다. 줄이거나 고치지 않는다.

## 5. 모양과 간격

- 둥근 모서리: 카드 16px, 버튼·입력창 10px, 카드 안의 칸 12px, 호재·악재 칩 6px, 배지·세그먼트 버튼 999px.
- 테두리: 카드는 1px `--line`. **2px 테두리는 판단 카드만** 쓴다(화면의 기준점). 왼쪽 세로 막대 장식은 쓰지 않는다.
- 레이아웃: 한 열, 최대 폭 720px, 양옆 여백 16px 이상(노치가 있는 기기는 안전 영역만큼 더). 카드 사이 16px, 카드 안 여백 24px(폭 600px 이하에서는 20 / 16px).
- 칸 구분은 테두리를 더하기보다 `--surface` 배경으로 한 단계 들인다.

## 6. 상태

**누를 수 있는 것** (실제 `button`, `a`만 쓴다)

| 상태 | 표현 |
|---|---|
| 기본 | 배경 없음 또는 `--line` 테두리 |
| hover | 배경 `--fill-hover`, 테두리 `--line-hover` |
| 누름·선택(패널에 열린 줄 포함) | 배경 `--fill-selected` |
| 포커스 | 2px `--focus` 테두리, 3px 띄움. **절대 빼지 않는다** |
| 쓸 수 없음 | 투명도 .4, 커서 기본 |

- 누를 때 크기를 바꾸지 않는다(scale, 이동 없음). 배경과 테두리 색만 바뀐다.
- 누를 수 없는 카드에는 hover를 두지 않는다.
- 누르면 무언가 열리는 줄에는 끝에 `›`를, 바깥(DART)으로 나가는 링크에는 `↗`를 붙인다. 접고 펴는 것은 아래 화살표가 돈다.

**판단 카드의 상태 다섯 가지**: 호재 / 악재 / 중립 / 판단 보류(배지와 카드 테두리를 점선으로) / 분석 실패(지난 판단을 투명도 .55로 흐리게 보여주고, 원인 한 줄과 "다시 불러오기" 버튼).

**비어 있거나 없는 것은 이유를 말한다.** "이날 들어온 공시는 없어요", "중립 공시는 요약하지 않아요", "요약을 아직 만들지 않았어요. 다음 분석 때 채워져요"처럼 왜 없는지와 언제 생기는지를 쓴다.

## 7. 움직임

- 기본 전환: 0.2초, `cubic-bezier(0.4, 0, 0.2, 1)`. 이 하나만 쓴다.
- 쓰는 곳: 색·테두리 전환, 접기 화살표 회전, 패널 열림(오른쪽에서 밀려 들어옴, 시트는 아래에서), 막 나타남, 새로 들어온 항목을 1.2초 밝혔다가 원래대로.
- 쓰지 않는 것: 크기 변화, 흔들림, 튀는 곡선, 스크롤에 따라 움직이는 연출, 저절로 도는 슬라이드, 숫자 올라가는 효과.
- 사용자가 움직임 줄이기(`prefers-reduced-motion`)를 켜 두었으면 전환과 애니메이션을 모두 끈다.

## 8. 화면 패턴

- **종목 화면은 위에서 아래로 한 줄 흐름**이다: 회사 이름 → 판단 카드 → 판단 추이 → 실적(접힘) → 타임라인.
- **탭은 쓰지 않는다.** 정보가 많으면 덜 중요한 것을 접는다(나머지 근거, 실적). 기간처럼 같은 내용을 다른 범위로 보는 선택만 세그먼트 버튼으로 둔다.
- **공시 한 건은 공시 패널로 연다.** 화면 오른쪽에서 열리는 폭 440px 패널이고, 폭 640px 이하에서는 아래에서 올라오는 시트(화면 높이의 88%까지)다. 어디서 누르든 같은 패널이 열린다.
  - 열면 포커스가 닫기 버튼으로 가고 뒤 화면은 누를 수 없게 막는다. Esc, 바깥 막 누르기, 닫기 버튼, 뒤로 가기로 닫힌다. 닫으면 포커스가 누른 줄로 돌아간다.
  - 패널이 열린 동안 그 공시의 줄은 선택 상태로 보인다.
  - 공시마다 주소(접수번호)가 붙는다. 패널 안의 이전·다음은 주소를 바꾸기만 하고 뒤로 가기 기록을 쌓지 않는다.
- **소식은 세로 타임라인**으로 보여준다: 다가오는 일정 → 오늘 → 지난 공시. 선 위의 표시도 모양(▲ ▼ ● ○)으로 구분한다.
- 숫자 점수는 공개 화면에 보이지 않는다. 판단은 다섯 단계 이름과 수평 막대로 보여준다.

## 9. 접근성

- 글자 대비 4.5 : 1 이상(3-3).
- 손가락으로 누르는 기기에서 누르는 곳은 44px 이상이다.
- 누르는 것은 실제 `button`과 `a`로 만든다. `div`에 클릭을 달지 않는다.
- 그래프는 키보드(좌우 방향키)로도 날짜를 옮길 수 있고, 같은 내용을 글로도 보여준다.
- 색만으로 뜻을 전하지 않는다(3-2).

## 10. 문구

- 해요체로 쓴다. 짧게, 사실만.
- 매수·매도·추천·목표가·예측처럼 읽히는 표현과 시세를 안내하는 표현을 쓰지 않는다.
- 판단은 "최근 공시 기준"으로 범위를 밝힌다.
- 오류는 원인과 다음 행동을 쓰고 사과하지 않는다. 예: "11.06 공시 분석이 끝나지 않아 11.05 판단을 보여주고 있어요. 새 공시는 다음 분석 때 반영돼요."
- 판단 카드, 공시 패널, 화면 아래에 "AI 요약은 틀릴 수 있으며 투자 권유가 아니에요" 고지를 둔다. 공시·재무의 출처(DART)를 밝힌다.

## 11. 라이트 모드 (이후)

지금은 어두운 토큰 한 벌만 있다(`color-scheme: dark`). 라이트 모드는 3-1의 토큰 블록을 하나 더해 붙인다(`--tint`를 검정으로, 바탕과 글자색을 뒤집고, 호재·악재·AI 색은 밝은 바탕에서 대비를 다시 계산한다). 시스템 설정을 따를지 전환 버튼을 둘지는 붙일 때 정한다.
